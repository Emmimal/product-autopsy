# Product Autopsy

Checks whether a digital product (a spreadsheet, template pack, guide or starter kit) delivers what its listing promises. It reads a product folder the way a disappointed buyer would and tests every promise it can verify against the actual files.

Built for the DEV Hacktoberfest Open-Source AI Challenge, Week 2: Side Hustle. A small local model (Gemma 3 1B through Ollama) reads promises written in prose. Plain code decides what is true. A validator rejects model claims that fail the source-grounding and workbook checks and leaves them for human review.

**Write-up:** [Product Autopsy: My Auditor Flagged 18 Broken Promises in My Own Repos. Four Were Real](https://dev.to/emmimal_alexander_3be8cc7/product-autopsy-my-auditor-flagged-18-broken-promises-in-my-own-repos-four-were-real-bi1)

## What it checks

| Check | What it catches |
|---|---|
| Missing file | A document names a file that is not in the package |
| Broken link | A local Markdown link that does not resolve: missing target, wrong letter case, a path outside the package, or a `#anchor` with no matching heading |
| Spreadsheet total | A `SUM` whose range does not match its data, that sums a column with a different header, or whose result differs from the number the README promises |

Supported in this version: `.md` and `.txt` documents, local files and links, and `.xlsx` workbooks with `SUM` totals. Anything else is not checked and is never reported as a finding.

## Quick start

```
pip install -r requirements.txt
python gen_products.py
python autopsy.py samples/budget-planner --report
```

Example output:

```
Product Autopsy report: budget-planner
3 problem(s) found, 6 check(s) passed

FAIL  broken link   README.md: `docs/refund-policy.md` does not resolve (missing, or the letter case differs)
FAIL  missing file  README.md: `setup.xlsx` is named in the docs but is not in the package
FAIL  spreadsheet   tracker.xlsx: `Total Revenue`: the SUM range does not match the data rows; the result differs from the number the README promises
```

## Run everything

```
python run_all.py                    # planted-defect benchmark, deterministic checks only
python run_all.py --real             # + scan of the 30 repos in clone_repos.py (needs git)
python run_all.py gemma3:1b --real   # + Gemma 1B experiments (needs Ollama running)
```

For the Gemma steps, install [Ollama](https://ollama.com), run `ollama pull gemma3:1b` once, and keep `ollama serve` running. Results are saved to `results.md`.

## Results

| Experiment | Result |
|---|---|
| Planted-defect benchmark (30 defects, 60 valid controls) | 93% recall, 100% precision, 0% false positives |
| Free-phrased promises, one-sentence READMEs (hold-out) | deterministic 0 of 10, Gemma 1B 8 of 10, 0 of 10 false alarms |
| Free-phrased promises, realistic READMEs (hold-out) | deterministic 0 of 10, Gemma 1B 5 of 10 in run 1 and 4 of 10 in run 2, 0 of 10 false alarms |
| Scan of 30 of the author's own repos | 216 checks, 18 flagged, 4 confirmed defects after hand review, 14 false alarms |
| Same scan after the fixes | 14 flagged, all classified as false alarms |

The benchmark products and the hold-out sets are synthetic and generated by the scripts here. Ten defects per hold-out setting is a small sample, and the realistic-README result varied between two runs with the same code and data. See the [write-up](https://dev.to/emmimal_alexander_3be8cc7/product-autopsy-my-auditor-flagged-18-broken-promises-in-my-own-repos-four-were-real-bi1) for the full discussion.

## Files

| File | Purpose |
|---|---|
| `autopsy.py` | The deterministic checker and the `--report` mode |
| `extract_claims.py` | Gemma claim extraction through Ollama, with schema and source-grounding validation |
| `gen_products.py` | Generates the 10 benchmark products with 30 planted defects and the ground truth |
| `gen_phrasing.py` | Generates the free-phrasing hold-out sets (`--noisy` for realistic READMEs) |
| `run_benchmark.py` | Scores the checker against the ground truth |
| `scan_repos.py`, `clone_repos.py` | Scan real repos and clone them |
| `run_all.py` | Runs everything and writes `results.md` |
| `show_claims.py` | Prints the claims Gemma produced from `gemma_debug.json` |

## Known limits

- The file-mention check flagged 18 candidates in the author's repos and 4 were real, so it finds candidates but is not ready to trust unattended.
- It skips fenced code blocks, so a file listed only in a code-fenced tree can be missed.
- It reads files and does not run a product's instructions, so a broken Quick Start is invisible to it.
- Gemma 1B is useful but fragile: recall dropped when the promise sat inside a realistic README.
- The validator reduces one class of model error. It does not guarantee that every accepted finding is correct.
